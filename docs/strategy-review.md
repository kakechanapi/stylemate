# 戦略レビュー — 予測市場アプリ
> 作成日: 2026年3月 | ステータス: Phase 0 設計レビュー

---

## 総評

設計の方向性は正しい。特に「ポイント制（無償付与）」による法的リスク回避と、「Yes/No バイナリー」によるシンプルさの徹底は、日本市場での予測市場立ち上げに適したアプローチ。以下に強み・懸念点・改善提案を整理する。

---

## 強み（Keep）

### 1. 法的設計の慎重さ
- 現金不使用・無償ポイント付与のモデルは、賭博法抵触リスクを大幅に低減する
- 弁護士レビューを「最優先」と明記している点は正しい判断

### 2. 技術スタック選定
- Expo + Supabase の組み合わせは一人開発に最適解
- 月額コスト ¥35,000〜¥60,000/年 は現実的かつ持続可能
- Claude Haiku を使った質問生成は低コストで高品質な運用が可能

### 3. クローズドβ戦略
- 最初に50名のコアユーザーで検証してからオープンβに進む段階設計は正しい
- 口コミ・シェア機能によるオーガニック拡散の戦略はコスト効率が良い

---

## 懸念点（Risk）

### 1. コミュニティ投票オラクルの脆弱性（最重要）
**問題**: コミュニティ投票で結果判定する設計は、初期ユーザー数が少ないMVP段階では機能しない可能性が高い。
- ユーザー50名 → 実際に判定投票する人は10名以下になる可能性
- 判定操作（身内で結果を誘導）のリスク

**提案**:
- MVP段階は**運営が手動で判定**する「管理者判定モード」を用意する
- 判定基準をドキュメント化し、透明性を担保する
- ニュースAPIとの自動判定は v2 からでよいが、候補として NHK RSS・時事通信 API を調査しておく

### 2. ポイント交換の複雑性
**問題**: 「ポイントをギフトカードに交換可能」という設計は魅力的だが、以下の運用コストが発生する。
- ギフトカード在庫管理・発行コスト（Amazonギフト券等）
- 不正交換（複数アカウント）への対策
- 景品表示法上の「懸賞」判定リスク（1回あたりの最高額制限）

**提案**:
- MVP段階は交換機能を「お知らせ予定」として UI には表示するが、**実際の交換は手動申請制**にする
- 月額・累計の交換上限を設けてシステムで制限する
- 当面は「名誉称号・バッジ」のみのゲーミフィケーションでも十分リテンションは取れる

### 3. AI質問の品質管理が設計されていない
**問題**: Claude APIで自動生成した質問をそのまま配信すると、以下のリスクがある。
- 事実確認が取れない・判定不能な質問の生成
- 政治的に偏った質問
- 日本語として不自然な質問

**提案**:
- 生成→**人間レビュー（自分）→公開**の2ステップフローを設ける
- 質問生成時にプロンプトで「判定可能性チェック」を組み込む
- カテゴリ別（政治・スポーツ・経済）に異なるプロンプトテンプレートを用意する

### 4. App Store 審査リスクの過小評価
**問題**: Apple は「賭け・ポイント交換」を含むアプリに厳しい。
- 審査ガイドライン 4.3（スパムアプリ）・5.2（コピーライト）も注意が必要
- 「ギャンブル」カテゴリに誤分類されると審査が非常に困難になる

**提案**:
- App Store Connect のカテゴリは「教育」か「ライフスタイル」で申請する
- キーワード・説明文から「予測」「的中」「賭け」などのワードを避け「情報収集」「集合知」に寄せる
- MVP段階は **TestFlight のみ**（公開審査なし）でクローズドβを実施する

## 追加提案（Add）

### 1. ドメイン・ブランディングを早期に確定する
- アプリ名・ドメイン・SNSアカウント（@xxx）を早めに押さえる
- 「予測」というワードを前面に出しつつ、知的でカジュアルなブランドイメージを設計する

### 2. オンボーディング設計が重要
- 予測市場の概念を知らない日本人ユーザーが多数
- 初回起動時に「どうやって遊ぶか」を30秒で理解させるチュートリアルが必須
- 最初の予測は「今日の天気」「今日の日経平均」など身近なものにするとハードルが下がる

### 3. 管理ダッシュボードを早期に作る
- 質問の承認・却下、判定の実行、不正ユーザーのBANを行う管理画面
- これがないと運営が詰まる。Supabase Studio + 簡単な管理用Webページで十分

### 4. Brier スコアの導入を検討する
- 「的中率」だけでなく、予測の信頼度（何%で予測したか）を評価する Brier スコアを採用すると、より本格的な予測精度記録が可能
- Metaculus が採用している方式で、ユーザーの予測スキルをより正確に評価できる

## 結論

このプロダクトは「日本に予測市場文化を作る」という明確なビジョンがあり、技術・コスト・法的リスクのバランスも良く設計されている。最大の実行リスクは「法的クリアランスの遅れ」と「コミュニティ判定の機能不全」。この2点を最初に解決すれば、MVPは十分実現可能なレベルにある。

**次の一手**: 弁護士相談 + TestFlight クローズドβ準備 の並行実施。
