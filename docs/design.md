## 1. プロダクトビジョン
### ミッション
- 日本の市民が簡単に予測市場にアクセスできるようにする
- 集合知を活用して確かな情報で日常の判断をサポートする
- 予測を「賭け」ではなく「考える習慣」として文化に根付かせる

### 1.1 解決する課題
予測市場は海外（Polymarket・Metaculus等）では普及しているが、日本では以下の課題から一般市民には未普及：
- 金銭を扱う予測市場は日本の賭博法に抵触するリスクがあり、参入障壁が高い
- 英語・海外サービス中心で、日本の社会問題・政治・エンタメに特化したサービスがない
- UIが複雑で専門知識が必要なため、一般ユーザーへのハードルが高い

### 1.2 プロダクトの核心価値
| 価値 | 説明 |
|------|------|
| **シンプルさ** | Yes / No のバイナリー予測でだれでも参加できる |
| **安全性** | ポイント制（ギフトカード交換可）で法的リスクを最小化 |
| **楽しさ** | ゲーミフィケーション＋カジュアルUIで日常的に使いたくなる |
| **信頼性** | リアルタイムオッズ＋過去精度記録で集合知の価値を可視化 |
| **コミュニティ** | 友達・ランキング・グループ予測でソーシャル体験を提供 |

## 2. ターゲットユーザー
### 2.1 ペルソナ一覧
| ペルソナ | 特徴 | 主な動機 | 獲得チャネル |
|----------|------|----------|-------------|
| 学生・若年層 | 18〜30歳、SNS活発、トレンド敏感 | 楽しさ・ランキング競争・友達との比較 | Twitter / TikTok / クローズドβ |
| 一般市民 | 30〜50歳、政治・社会関心層 | 世の中の動向を先読みする知的楽しみ | ニュースアプリ連携・メディア |
| 投資家層 | 情報リテラシー高・経済予測に興味 | 経済・マーケット予測の精度向上 | FinTechコミュニティ・Twitter |
| 政治関心層 | 選挙・政策に関心がある市民 | 政治予測の的中・社会への発言力 | 政治系コミュニティ・Discord |

### 初期ユーザー獲得戦略（MVP）
- まず知人・クローズドβで 10〜50人のコアユーザーを確保
- フィードバックを徹底収集し、プロダクトを磨いてからオープンβへ
- Twitterでの予測結果シェア機能で口コミ拡散を狙う

## 3. 機能要件
### 3.1 MVP（最小構成）に含める機能

#### ① 予測市場コア
- **バイナリー予測（Yes / No）形式のみ**に絞ってシンプルに
- AIが自動生成した質問を定期配信（政治・経済・スポーツ・社会問題）
- リアルタイムオッズ表示（全体の投票比率を % で可視化）
- 結果判定：コミュニティ投票で判定（フラグシステム導入）
- 過去の予測精度スコアをプロフィールに記録・表示

#### ② ポイントシステム
- 参加・的中でポイント獲得
- ポイントはギフトカード等に交換可能（無償付与のみ・現金入金なし）
- 毎日ログインボーナス・連続的中ボーナスでリテンション向上

#### ③ ソーシャル機能
- グローバルランキング・週間ランキング
- フレンド機能：友達とのグループ予測・内輪ランキング
- プロフィール：的中率・予測数・バッジを表示

#### ④ ゲーミフィケーション
- レベルシステム（予測数・的中率でレベルアップ）
- バッジ（「連続的中」「政治予測の神」等の称号）
- 実績（アチーブメント）システム

### 3.2 MVP後（v2.0以降）に追加する機能
- マーケットメイカー機能（流動性提供者の導入）
- ユーザー投稿型の質問（AIと人間のハイブリッド）
- コメント・議論スレッド
- 通知機能（締切間近・結果確定）
- カテゴリ別フィード（パーソナライズ）

## 4. 法的・コンプライアンス設計
> **最重要リスク：賭博法・景品表示法への抵触**
>
> - 日本の刑法185条・186条（賭博罪）の射程に入らないよう設計が必要
> - 景品表示法：ポイントの交換価値が高すぎると「懸賞」扱いになるリスク
> - 資金決済法：ポイントの設計次第で「前払式支払手段」に該当する可能性

### 4.1 安全なポイント設計
| 項目 | 方針 |
|------|------|
| **設計原則** | ユーザーが現金を投入してポイントを購入しない（無償付与のみ） |
| **付与方法** | ログイン・予測参加・的中・招待等の行動報酬として無償付与 |
| **換金上限** | 景品表示法の懸賞上限（最大取得額10万円）を参考に上限設定 |
| **法的根拠** | 「くじ」や「賭博」でなく「懸賞・プレゼント」として設計 |
| **弁護士相談** | リリース前に景品表示法・賭博法専門の弁護士に**必ず確認** |

### 4.2 オラクル（結果判定）設計
- 投票操作・グルーピングによる不正防止の仕組みが必須
- 判定期間・投票権資格（一定以上のアクティビティが必要等）を明確化
- 争議が発生した場合の運営介入フローを事前に設計
- 将来的には外部ニュースAPIとの自動判定ハイブリッドへ移行を検討

### コンプライアンス対応チェックリスト（リリース前）
- [ ] 景品表示法・賭博法専門弁護士によるレビュー完了
- [ ] 利用規約・プライバシーポリシーの整備（個人情報保護法対応）
- [ ] ポイント換金上限の設定と監視システムの実装
- [ ] 年齢確認フローの実装（未成年者保護）
- [ ] 不正検知・アカウント凍結フローの設計
- [ ] Apple / Google ストアのガイドライン確認（ギャンブル系アプリ規制）

## 5. 技術スタック推奨
**前提条件：一人開発・シャブコ予算（数十万円以下）・モバイルアプリ**

### 5.1 推奨スタック
| レイヤー | 推奨技術 | 理由 |
|----------|----------|------|
| **フロントエンド** | Expo (React Native) | iOS/Android同時開発。一人開発に最適。OTAアップデートで審査不要の小修正が可能 |
| **バックエンド/DB** | Supabase | PostgreSQL+Auth+リアルタイム購読をゼロコストで提供。無料枠で十分スタート可能 |
| **AI質問生成** | Anthropic Claude API | claude-haiku-4-5で低コスト自動質問生成。1問あたり約0.01円以下 |
| **認証** | Supabase Auth | メール・電話・Google/SNSログインをネイティブサポート |
| **プッシュ通知** | Expo Notifications | ExpoのPush Notification APIで簡単実装 |
| **ホスティング** | Vercel / Supabase | フリープランで十分。スケール時はPro移行 |
| **CI/CD** | GitHub Actions | 無料枠で自動テスト・ビルド |

### 5.2 月次コスト試算（MVP段階）
| 項目 | コスト |
|------|--------|
| Supabase Free | ¥0（DB・Auth・Realtime込み） |
| Expo / EAS Build | ¥0〜¥2,000 / 月（30ビルドまで無料） |
| Claude API（質問生成） | ¥500〜¥2,000 / 月（1日10問 × 30日） |
| Apple Developer | ¥14,900 / 年 |
| Google Play | ¥3,000（初回のみ） |
| **合計（初年度）** | **約 ¥35,000〜¥60,000 / 年** |

## 6. UX・デザイン設計
### 6.1 デザイン原則
| 原則 | 説明 |
|------|------|
| **カジュアル＆楽観的** | 重厚な「金融アプリ」感を排除。明るい色使い・丸みのあるUI |
| **シンプルファースト** | 1画面1アクション。「Yes / No」の2タップで予測完了 |
| **ゲーム感覚** | レベルバー・バッジ・ランキングをホーム画面に常時表示 |
| **信頼感** | 的中率・根拠リンクを各予測に自動添付 |

### 6.2 主要画面フロー
```
ホーム
 └── 本日の注目予測カード（3〜5件）＋自分のランキング順位
予測詳細
 └── 質問・現在オッズ・締切日・Yes/Noボタン・根拠リンク
結果フィード
 └── 解決済み予測の一覧・自分の的中/外れの履歴
プロフィール
 └── 的中率グラフ・バッジコレクション・ポイント残高
フレンド
 └── 友達ランキング・グループ予測作成
```

### 6.3 ログイン設計
- メールアドレス（OTP）
- 電話番号 SMS 認証
- Google / Apple / LINE ソーシャルログイン

→ Supabase Auth で全方式をネイティブサポート。最初の画面でどれでも選べるよう設計。

- [ ] 予測投稿・参加・オッズ表示

## 9. リスクと対策
| リスク | 深刻度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| 法規制（賭博法・景品表示法） | 高 | 中 | リリース前の弁護士レビュー。ポイントは無償付与のみ。換金上限設定 |
| 技術的複雑さ（リアルタイム・スケール） | 中 | 中 | Supabaseのリアルタイム購読で実装。MVPは機能を絞り複雑性を排除 |
| コミュニティ投票の不正 | 中 | 中 | 投票権に最低アクティビティ要件。フラグシステム＋運営介入フロー |
| App Store審査リジェクト | 高 | 中 | ガイドライン事前確認。ギャンブル要素の誤解を招かないUI・説明文 |
| ユーザー獲得コスト | 中 | 高 | クローズドβで口コミを先行。シェア機能でオーガニック拡散を狙う |
